# Security operations

This is the deployment and recovery runbook for the single-author security update. Repository changes do not apply GitHub rules, provision buckets, migrate production D1, set secrets, or configure Anthropic accounts by themselves. Complete the activation steps before enabling submissions and automated publication.

## Boundaries

- The hub accepts one author per motion. The immutable `accounts/` mapping resolves both current and former logins to the same numeric GitHub id. An update cannot transfer authorship. Credits and `basedOn` grant no permissions. Older format versions retain their format meaning; single authorship is a hub admission rule.
- Anonymous uploads go only to `motionhub-submissions`. Main is read at an immutable SHA, and the intended author is verified before `owner_id` is stored. Only that account can preview files or confirm publication. A link or a polling token grants no draft access.
- A submitted package is immutable and its digest is checked on every read. A D1 lease and a unique active-motion index serialize submissions. GitHub's expected head prevents concurrent branch replacement; a retry reconciles its signed submission marker rather than blindly committing twice.
- `share/**` branches belong to the submission App, not Claude. Every PR commit must carry a valid GitHub verification for the expected App and the same submitter id. The App's Git commit identity is the App; the human's DCO and account id are recorded in its signed message.
- Build, render, inference, and packaging runners have no production credentials. Fresh publishing runners verify artifacts from the current run before using credentials. R2 writes use atomic `If-None-Match: *`; a 403, timeout or server failure is never interpreted as object absence.
- The Claude workflows call the Messages API without tools. They do not use Claude Code or `CLAUDE_CODE_OAUTH_TOKEN`, run code, apply patches, push, approve, merge or deploy. Optional patches are untrusted artifact data for a person to inspect. Model results cannot select a publication target or survive a changed PR head.

## Activate this release

1. Set the repository variable `PUBLISHING=off` and disable the existing Worker submission intake while preparing the change. Keep `CLAUDE_ENABLED` absent or `false`. Do not expose a private draft or credential to a public PR, workflow artifact, model prompt or log.
2. Export a production D1 recovery copy into `.security-backups/`, an ignored local directory with restricted access. Verify that the export can be restored to a separate test database. Do not attach the export to an issue or Actions artifact.
3. Create the private R2 bucket `motionhub-submissions`. Keep both its `r2.dev` access and custom domain access disabled. Apply `.cloudflare/submissions-lifecycle.json` to this bucket only, preserving any other needed lifecycle rules. This is asynchronous cleanup; the API independently enforces expiry at read time.
4. Apply `site/migrations/0006_submission_security.sql` with the project's pinned Wrangler D1 migration command. Legacy pending links deliberately expire; users must upload again. Historical submitted records remain, but legacy preview links without an owner binding are not restored. Host-only `__Host-` cookies remain compatible with the current main authentication and Artifact CLI sign-in.
5. Add production environment secrets: `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_DEPLOY_TOKEN`, `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY`. The S3 credentials are read/write credentials restricted to the **published** `motionhub` bucket. The deployment token uses the smallest supported Worker/account/route permissions; it is not a general account administrator token. Deploy authority can indirectly expose runtime bindings, so treat it as sensitive even though a secret cannot be read through the management API. Remove the old job-wide `CLOUDFLARE_API_TOKEN` secret after verification.
6. Review and apply `.github/rulesets/main.json` to the existing main ruleset rather than accidentally creating conflicting rules. Generate the App-only branch rule with `node .github/scripts/submission-ruleset.mjs <numeric-submission-App-id>`; inspect its JSON and apply it through GitHub administration. The template without an App id intentionally grants no bypass. Set `MOTIONHUB_BOT` to the App's verified bot login. App installation permissions are contents/write and pull requests/write on this repository only. Do not give it main bypass.
7. Configure the `production` environment for main-only deployments and the `npm-release` environment for protected release tags. npm Trusted Publisher must reference this repository, `publish.yaml`, and `npm-release`. Preserve staged release approval with 2FA. Restrict release tag creation to maintainers. Each tag must point into reviewed main history. The fixed publication jobs must be reviewed before environments are approved.
8. After this PR is merged and the prerequisites are ready, set `PUBLISHING=on` and repository variable `SUBMISSIONS=off`, then dispatch the main deployment. The deploy job maps this variable to the Worker's `SUBMISSIONS` setting; absence defaults to off. The workflow deploys the pure static `motionhub-player` Worker at `player.motionhub.dev` before the account site. Ensure that custom domain is available in the intended zone and the deploy token can manage these two Workers. Verify cookies, logs, bindings and the draft-denial tests while intake remains paused.
9. Publish CLI 0.9.0 from the merged main commit through the staged npm process and approve it before enabling the new upload flow. Old CLI query-string polling receives an explicit upgrade response. Package files include `tools/security/` so installed clients use the same checks. Then set `SUBMISSIONS=on` and dispatch another deployment. Test using a non-production motion/account first. Existing unsigned App PRs must be closed and resubmitted before the new verified-commit gate accepts them.
10. To enable AI advice, configure a dedicated Anthropic API workspace/key with its own spend limit and retention settings. Add repository secret `ANTHROPIC_API_KEY`, set `CLAUDE_MODEL` to an explicitly selected available model id, then set `CLAUDE_ENABLED=true`. Subscription OAuth credentials are not a substitute for this API key; API billing is separate. Test `/review` on a harmless PR. Reviews now require a maintainer request; there is no automatic expensive review on contributor pushes.
11. Remove obsolete Claude GitHub App write access and its OAuth secret if they have no other use. Check and update CODEOWNERS and any explicit GitHub login configuration when a maintainer renames their account.

The main ruleset does not require an App branch to merge unrelated main commits: these protected branches stay App-signed and linear. The main deployment rechecks the complete merged catalogue. The ruleset requests an independent approval, dismisses stale approvals and requires approval of the latest push. All repository paths now have a code owner. With only one maintainer, an administrator can use the **PR-only** bypass with an explicit self-review record; this is not independent two-person review. No App gets that bypass. Once there are two reviewers, remove routine administrator bypass.

## Data and retention

A draft is readable for at most 24 hours. Cron and R2 lifecycle remove its package afterward; physical deletion can lag. The upload budget defaults to 1,000 attempts per UTC day across the service, in addition to per-IP throttling and five confirmed submissions per author per day. `UPLOADS_PER_DAY` can change the global budget within the server's validated bounds. Incorrect codes count only after owner authentication.

Sessions last 30 days and are stored as hashes; expired sessions are swept. Forget me deletes this person's draft objects before deleting their private records. If object deletion fails, the operation returns a retryable error and keeps the metadata needed to retry. GitHub PRs and published package history are already public and are not erased by account deletion.

Worker query strings are redacted. Application logs contain event names and aggregate sweep results, not body contents, cookies, tokens or request authorization. Keep log readers restricted and use the shortest operational retention available. Cleanup failures emit named error events; configure an alert for `submission_*_failed` and for repeated deployment failures. Actions artifacts contain only scanned public review material or intended public release content, with one-day AI and three-day release retention.

The portable scanner refuses known credential paths, private keys and recognized token patterns. It does not prove a file contains no secrets. Gitleaks separately scans committed history with redacted reports. Always inspect the CLI's source directory and file list before publication; a closed public PR is not a private draft.

## Pause and recover

- Set `PUBLISHING=off` to stop subsequent deploy, render publication and npm staging runs. Cancel any already-running publishing job separately.
- Set `CLAUDE_ENABLED=false` and cancel active AI runs to stop advice generation. A request already sent to the provider may still be billed.
- For immediate intake suspension, set the Worker's `SUBMISSIONS=off` in Cloudflare. Also set repository variable `SUBMISSIONS=off`, so the next deployment preserves the pause. Intake pause does not make existing private files public.
- For a suspected leaked credential, revoke it at its provider, replace the narrowly scoped credential, and inspect associated commits/deployments. Deleting a log or removing a file is not credential revocation.
- Roll back to a previously verified release artifact on a fresh publishing runner. Do not roll back to the old authorization code or remove the D1 security columns. Keep intake paused until the updated checks pass.
- For a malicious published version, suspend publication, quarantine its delivery path, purge caches and publish a fixed version with a clear advisory. Downloaded copies cannot be recalled. Keep an incident record of the account id, commit SHA, package digest and affected URLs without copying credentials into it.

## Verification

Run `npm test`, `node tools/check.mjs`, `node tools/build.mjs`, `npm run build` in `site/`, and `npm run smoke` there. Smoke includes the browser regression for direct `/play/` navigation: no cookie, storage, API or popup access. Validate all workflows with actionlint. Test artifact changes, foreign run ids, wrong source commits, R2 403/500 and competing conditional writes before activating production.

The normal production embed uses the separate `player.motionhub.dev` origin. `wrangler.player.jsonc` has static assets only, with no D1, R2, OAuth, App or secret binding. The build copies only `/play/` and its headers into that release artifact; deployment overrides the intentionally absent local `dist-player/` directory. Local builds default to a relative player URL. Production CI sets `PUBLIC_PLAYER_ORIGIN` to the fixed player origin, and refuses an unexpected origin. The main origin retains sandboxed legacy `/play/` URLs so old links keep working; browser tests cover this fallback too. Verify the deployed hostname, response CSP, cookie scope and frame behavior before claiming production isolation.
